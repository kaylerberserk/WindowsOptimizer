# Audit de WindowsOptimizer — octobre 2026

Ce rapport remplace les versions précédentes, qui accumulaient des constats dont plusieurs se sont
révélés faux. Il ne garde que ce qui a été mesuré, et dit où.

## En bref

- Le script a été **exécuté en entier pour la première fois avec relevé avant et après**, sur une
  installation neuve de Windows 11 : `Tout optimiser` en Gaming + Performance max, redémarrage,
  puis Normal + Eco, redémarrage. Il va au bout dans les deux sens et la machine redémarre.
- L'aller-retour est **réellement réversible** sur les axes annoncés : réseau, heuristiques TCP et
  configuration de démarrage reviennent à l'identique.
- Trois lots de correctifs : PR #7, PR #8 et la branche `audit/vm-e2e-2026-10`. Les défauts les
  plus sérieux sont listés ci-dessous.

## Deux environnements de mesure

| | pc-gaming | VM de test |
|---|---|---|
| Système | Windows 11 25H2 (build 26200) | Windows 11 Entreprise d'évaluation, build 26300, français |
| État | **déjà modifié** : Gaming + Performance max, des dizaines de lancements | **neuf**, instantané restaurable |
| Sert à | tester un helper isolé sur du vrai matériel | valeurs stock, exécutions complètes, redémarrages |

Règle retenue après plusieurs erreurs : **une valeur que le script écrit, relevée sur pc-gaming, ne
prouve rien sur Windows**. Toutes les valeurs « stock » de ce rapport viennent de la VM.

La VM vit sur hp-dev dans `~/vms/winopt/` (QEMU/KVM, TPM et Secure Boot actifs). `lab.sh` la remet
à neuf, lance le script détaché dans la session interactive avec les touches fournies, et rapatrie
le journal et l'état. Limites de la VM : pas de GPU ni de carte réseau réels, édition Entreprise,
un seul build.

## Défauts corrigés

### Trouvés par l'exécution complète en VM

| Défaut | Conséquence pour l'utilisateur |
|---|---|
| « Défaut Windows » (sécurité) échouait dans le cas courant | `bcdedit /deletevalue` renvoie 1 quand `hypervisorlaunchtype` est déjà absent. Le registre était restauré, mais le script annonçait un échec et gardait les captures. |
| Restauration MSI en profil Normal | Toujours en échec dès qu'un périphérique portait déjà la valeur : la clé était ouverte en lecture seule. |
| Accents cassés sur l'écran d'accueil | Fichier écrit en UTF-8, relu par `cmd` en page de codes OEM : « Carte vidéo de base Microsoft » devenait illisible. |
| `[AVERTISSEMENT]` systématique en Performance max | Quatre réglages propres aux pilotes Intel, AMD, ATI et aux portables à deux GPU comptaient comme des erreurs, alors qu'aucune machine ne les a tous. |
| `[FAIT]` suivi d'une phrase d'échec | Deux appels plaçaient l'explication d'un échec là où s'affiche le détail d'un succès. |
| Deux valeurs supprimées au lieu d'être rendues | `KeyboardDataQueueSize` (stock 100) et `SfTracingState` (stock 1) en profil Normal. |

### PR #7 et #8

- **OneDrive** : la désinstallation ne supprime plus `%USERPROFILE%\OneDrive` quand Bureau,
  Documents ou Images y sont redirigés.
- **`RunAsPPL`** : `2` au lieu de `1`. `1` écrit une variable UEFI qui ne s'enlève plus par le
  registre. `2` est aussi la valeur d'un Windows neuf (mesuré).
- **Section 7.13** : un `| Out-Null` après un `call` arrêtait le script en plein milieu.
- **Section 1.1, profil Normal** : une ligne de commentaire sans `REM` s'exécutait comme une commande.
- **Animations** : passage par `SystemParametersInfo`. Les valeurs écrites auparavant n'étaient
  lues par rien. Vérifié en VM : le masque passe de `9E1E0780 12000000` à `90100780 10000000`.
- **DNS chiffré d'Edge et Chrome** : `allow` n'existe pas, remplacé par `automatic`.
- **Recall** : les écrans annoncent la suppression des instantanés, comportement documenté.
- **Menus** : un `choice.exe` en échec ne boucle plus. Vérifié en VM : entrée épuisée, sortie propre.
- **Menu « Devenir Propriétaire »** : état d'origine capturé puis rendu. Sur un Windows neuf la clé
  n'existe pas (mesuré) ; elle est donc supprimée à la restauration. Vérifié en VM.
- **Applications préinstallées** : cinq noms de paquets ne correspondaient à rien. Hub de
  commentaires et Assistance rapide portent bien les nouveaux noms sur un Windows neuf (mesuré).
- **Sauvegardes** : purge à 5 copies.
- **`MsMpEngCP.exe`** : écriture retirée, Windows la refuse.

## Ce que l'exécution en VM établit

| Étape | Résultat |

### Ce qui revient à l'état neuf, et ce qui ne revient pas

| Domaine | Après l'aller-retour |
|---|---|
| `netsh int tcp` (global, supplemental, heuristics) | **Identique au stock** |
| `bcdedit` | **Identique au stock** |
| Sécurité (VBS, HVCI, LSA) | Capture réimportée, puis supprimée |
| Plan d'alimentation | Équilibré actif ; le plan « Performances optimales » reste dans la liste (voulu) |
| Registre suivi | 186 entrées encore différentes sur 347 |

Sur ces 186, **40 ne sont que des clés vides** laissées derrière une suppression : aucune valeur n'y
diffère. Les **146 valeurs réellement différentes** sont pour l'essentiel la confidentialité et
l'interface, annoncées comme définitives. Hors de ce périmètre il reste la souris sans accélération
(choix de l'auteur pour les deux profils) et des réglages d'Explorateur et de l'Assistant de
stockage appliqués sans condition. Les tâches planifiées, les services de télémétrie et le fichier
`hosts` ne sont pas rendus : c'est le périmètre « définitif » du script.

## Laissé à l'auteur

Ce sont des choix d'axe, pas des bogues démontrés. Je n'y ai pas touché.

- **`NetworkPredictionOptions=0`** : « prédire sur toute connexion », donc plus d'activité réseau
  de fond, pas moins.
- **`pacingprofile=always`** : le lien avec BBR2 annoncé dans le commentaire reste à sourcer.
- **`EnableLUA=0`** pour retirer les confirmations : casse le mode d'approbation administrateur ;
  `ConsentPromptBehaviorAdmin=0` suffirait.
- **GameDVR** : désactivé pour tous les profils, sans chemin de retour.
- **Souris 1:1 en profil Normal** : écart volontaire avec le stock.
- **Écritures sans effet** listées plus haut : à garder ou à retirer.
- **`[FAIT]` sans relecture** : beaucoup d'étapes annoncent un succès sans relire la valeur écrite.

## Constats retirés

Présents dans les versions précédentes, et faux :

- « `LongPathsEnabled` vaut 1 au stock » : la valeur relevée venait du profil Gaming.
- « Aucun retour TCP possible » : la section Réseau en profil Normal fait ce retour, mesuré.
- « `ReadyBoot=1` est une inversion » : `1` est la valeur stock.
- « `HwSchMode` supprimé réactive HAGS à tort » : la valeur est absente au stock.
- « Une clé absente prouve un no-op » : `reg add` crée tout le chemin.

## Non couvert

- Windows 10, un portable, du vrai matériel GPU et réseau, une édition Famille ou Pro neuve.
- Les sections lancées une à une depuis le menu, le nettoyage, la désactivation de Defender et de
  l'UAC, la désinstallation d'Edge et de OneDrive, la suppression réelle des applications.
- Les transitions croisées Gaming + Eco et Normal + Performance max.

## Une erreur de test sur pc-gaming

Le 2026-10-03, un fragment de test mal découpé a exécuté les sections 1.8 à 1.17 du vrai script
sur pc-gaming, en session élevée. Toutes les valeurs écrites le sont aussi par chaque version du
script déjà lancée sur cette machine, sauf une : `DnsOverHttpsMode` d'Edge et de Chrome vaut
maintenant `automatic` (avant : `secure` ou `allow`). Depuis, les exécutions réelles se font
uniquement dans la VM.
